# Conversation tab: v2 fixes for dead props, dropdown dismissal, and draft lifecycle (v2)

Four issues from the v1 review are fixed. `onReply` now travels through `ConversationChatThread` to both user and agent turns. `onRewind` and `onFork` are wired from `ConversationsPrimaryView` to each `ConversationTurnBubble`. The view dropdown has a click-outside handler via `viewDropdownRef`. The `restoreDraft`/`stashedDraft` reset uses a `previousSessionIdRef` comparison inline during render.

The two acknowledged stubs (`handleStop`, model pill) remain `console.warn` and are out of scope for this pass.

Watch for: **`onReply` fires immediately on `mouseup` in the rich-chat path** (confirmed) — any non-empty selection invokes the handler directly without showing the selection bar, so users cannot choose "Copy" before the quote is injected. This is a behavioral inconsistency between the plain-turn and rich-chat paths. **None of the four fixes have test coverage** (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The `onReply` wiring in `ConversationChatThread` works, but the interaction model differs from the plain-turn path. `ConversationTurnBubble` shows a selection bar and lets the user choose Copy or Reply explicitly. `ConversationChatThread` calls `onReply` immediately on `mouseup` for any non-empty selection, bypassing the choice entirely. A user selecting text to copy in the rich-chat view will find their draft unexpectedly populated with a quote.

None of the four fix paths are covered by tests. The `onReply` asymmetry in particular is the kind of behavioral difference that breaks silently and is hard to notice through manual review.

## `onReply` asymmetry between rich-chat and plain-turn paths

In the plain-turn path, `ConversationTurnBubble` shows a `chat-selection-bar` with Copy and Reply buttons when text is selected. The user clicks Reply explicitly. In `ConversationChatThread`, the `AgentTurn` component and the user `<li>` have an `onMouseUp` handler that calls `onReply(selection.toString())` immediately on release, with no intermediate UI:

```tsx
// ConversationChatThread — AgentTurn
onMouseUp={() => {
  if (!onReply) return;
  const selection = window.getSelection();
  if (!selection || selection.isCollapsed || selection.toString().trim() === "") return;
  onReply(selection.toString());
}}
```

Any non-empty selection — including a drag-to-copy gesture — fires `onReply`, which sets `restoreDraft` in `ConversationsPrimaryView` to `> {selectedText}\n\n` and remounts the composer with that content. Users who select text intending to copy it via Cmd+C will find the quote has already appeared in the composer. This is **confirmed** by reading the component.

The fix is to add a selection bar in `AgentTurn` (and the user turn `<li>`) that matches the `ConversationTurnBubble` pattern: show Copy and Reply buttons, and only call `onReply` when Reply is clicked.

## Test coverage gaps introduced by the fixes

Not tested:

- `onReply` fired via `mouseup` in `ConversationChatThread` (the plain-turn tests cover `ConversationTurnBubble` only)
- `onRewind` and `onFork` props wired from `ConversationsPrimaryView` through to `ConversationTurnBubble` (the existing tests render `ConversationTurnBubble` directly with explicit props, not via the parent)
- View dropdown dismissed by `mousedown` outside the container
- `restoreDraft` and `stashedDraft` both reset to `null` when `selectedSessionId` changes
